# 真果鉴 · 红果短剧下载器

基于 `guoapp-src`（Flutter + Go native core）重写的 Windows 桌面客户端，把
**搜索 / 剧库推荐 / 在线观看 / 下载 / 合并**五件事装进一个 PyQt5 界面。

## 自检（验证打包成品）

```
dist\真果鉴.exe --selftest
```

在**打包后的二进制内**跑通全链路，而不是只看它能不能启动：

| 步骤 | 检查内容 |
| --- | --- |
| resources | 从 exe 同级定位 sidecar / mpv / ffmpeg / ffprobe |
| library | 分类推荐 + 四个榜单 |
| search | 联想词 + 搜索结果 |
| detail | 分集列表 |
| play | 无窗口驱动 mpv，经命名管道 IPC 确认 duration，并要求播放位置真的在推进（顺带验证属性事件通道） |
| preload | 解析并预热下一集，确认预取字节与过期时间 |
| download | 真实下载 2 集，core 写入加密缓存 |
| decrypt | 自动解密成可播放文件，按剧名分目录落盘 |
| merge | 解密 → 拼接 → 完整解码校验 → 成品落盘 |

GUI 是 `--noconsole` 构建，没有控制台，所以结果同时写到
`dist\selftest-report.json`。退出码 0 表示全通过。

最近一次实测（`dist\真果鉴.exe`，与根目录 `真果鉴.exe` 同一份）：`frozen=true`，
9 步全 OK，通常 15–45s（主要耗在下载 2 集，网络差时这一步到过 49s），产出

```
下载\穿越古代，我靠军火建立王朝\
  穿越古代，我靠军火建立王朝 第001集.mp4   12.2 MB  可直接播放
  穿越古代，我靠军火建立王朝 第002集.mp4    6.5 MB  可直接播放
  全001-002集.mkv                         18.7 MB  243.0s
```


开发期的验证脚本不随项目分发：需要哪一项检查就临时写一个跑一遍（见 git 记录/对话），
项目里只保留打包成品自检 `--selftest`。

## 快速开始

双击 `真果鉴.exe`。首次启动会初始化本地核心，约 2 秒后可用。

```
zhenguojian\
├─ 真果鉴.exe          主程序（单文件，约 38 MB）
├─ runtime\            外置组件，必须与 exe 放在一起
│  ├─ sidecar.exe      本地核心（内嵌 duanjuapp/native/core）
│  ├─ mpv\             播放器内核 + vulkan-1.dll（mpv 的静态依赖，缺它起不来）
│  └─ ffmpeg\          ffmpeg.exe / ffprobe.exe
├─ 下载\               成品库：每部剧一个文件夹
│  ├─ episodes.json      分集索引
│  ├─ <剧名>\           该剧的全部可播放分集
│  └─ 合并\             整季合并成品（可在「下载与合并」页单独删除）
└─ .cache\downloads\   core 下载的加密原件（不建议手动动）
```

> 下载和媒体库**都落在 exe 同级目录**，不在 C 盘。直接移动 exe 会失效，
> `runtime\` 目录要一起复制（尤其 `runtime\mpv\vulkan-1.dll`：没装 Vulkan 运行库的电脑少了它会提示「无法连接播放器控制通道」）。

## 功能

详情页采用整页滚动：上方海报和剧情资料、中间圆形演职员头像、下方自适应选集卡片，避免多层滚动和分割条挤压；长简介可展开/收起，复制仍包含全文。演职员头像通过实际图片解码显示，人员较多时可展开全部。

详情页现支持点击演员、导演或出品方头像查看关联作品；头像及身份使用平台返回的信息，无关联主页的人员不显示可用入口。个人资料接口暂不可用时仍显示剧集返回的姓名、身份和简介，作品列表独立可用。演职员信息包含主创用户列表，按个人主页返回的作品及子分类 ID 查询，兼容真人演员、漫剧人物、导演与出品方；已实测导演鲜馥成的 32 部关联作品。

「下载与合并」使用左侧完整剧集列表和右侧「下载队列 / 合并队列 / 合并成品」三个页签；支持按剧名搜索及状态筛选，保留勾选、整季合并和多季批量合并。

所有海报的悬停简介统一为紧凑的多行预览：长标题与简介自动换行，简介最多显示 180 字，超出部分以省略号结尾；完整内容可在剧集详情查看。适用于剧库推荐、找剧、搜索、新剧预约、上新日历、追更/预约和观看历史。

| 页签 | 说明 |
| --- | --- |
| 剧库 | 分类推荐（全部 / 真人剧 / 漫剧 / AI剧）和四个榜单；推荐海报与预约新剧统一为左下角热度、右下角集数，可见海报按批次补全缺失信息（每批最多 18 部，一次请求同时返回热度与集数）；推荐和左侧榜单均支持向下滚动自动追加内容，保留当前内容与滚动位置，加载失败可原地重试；榜单与海报区用留白分区，榜单滚动条仅在悬停或滚动时显示为细条；前 3 名使用橙/金/蓝名次徽标 |
| 找剧 | 服务器提供体裁、主题、设定、背景、推荐排序、受众、状态和上新时间八类组合筛选；多行筛选随窗口换行，可收起/展开、保留已选条件、一键重置；顶部关键词入口可搜索剧名。海报显示集数和热度，滚动自动续载，失败可原地重试 |
| 搜索 | 输入关键词即时联想，回车出结果，封面 HEIC 经 ffmpeg 转码显示；**优先走 H5 搜索接口 `/api/search/result/`，网页 `/search/<词>` 被字节风控成 500 时自动降级到联想词**；长剧名、带季号的剧也能直接命中；同一个词不会重复发请求，连续换词只认最后一次，搜索期间旧结果保持本色不变灰 |
| 剧集详情 | 海报、热度/追剧/播放指标、标签、完整简介、选集卡片；保留高清海报下载和复制完整简介。演职员头像可进入个人作品页，按角色查看已关联作品，支持分页、最新/已加载最热排序，再点海报打开其他剧集 |
| 播放 | mpv 内嵌窗口，命名管道 IPC 喂解密流，自动续播下一集、续播上次位置；换集复用同一个 mpv 进程（`loadfile replace`），不重新起进程、不黑屏；全屏会去掉页签容器边框和浅色底，画面真正铺满四边；选集是和剧集详情同一套芯片网格（侧栏点一下就换集，正在播的那集高亮、已下载的带角标）；进度条两边有上一集/下一集，空格键暂停继续，切到别的页签自动暂停、切回来接着放；全屏后 5 秒不动自动收起控制条，鼠标一动回来；**弹幕开关在控制条上（快捷键 D），旁边「透明 NN%」点开是竖向滑条，上下拖动调透明度**；弹幕按播放位置逐窗取（当前 30 秒 + 预取下一窗，和官方客户端一致，一次最多 90 条），转成 ASS 字幕轨交给 mpv 渲染，开关和透明度都记在 `app-settings.json` |

| 观看历史 | 每剧记录上次看到的位置，双击海报从上次位置续播、单击只选中（选中后才能删单条）；缺站源的老记录会自动补齐 |

| 下载 | 队列按剧分组，一集一张卡片：状态胶囊、**画质与码率**（`1080P · 1.46 Mbps`，取到流就显示，不必等下载完）、进度条、速度、**预计剩余时间（按实时速度推算）**、已下载/总大小，卡片上直接暂停/继续/播放/删除（双击已完成的行也能播）；顶部是打开目录、换保存位置、全部暂停/继续；启动时清理文件已不存在的成品记录 |
| 合并 | 合并按钮就在「当前剧集」卡片上：一键合并整季、合并选中分集、按季合并勾选的多部；状态栏按当前阶段显示**本阶段剩余时间**（阶段内长时间没有新进度时改显示已用时间，不再卡一个假倒计时）；左下角「合并成品」点一下播放、可单独删除。**换过下载位置以后，旧位置的成品仍然列在这里**（异盘标盘符如 `D:`，同盘标「旧位置」，悬停有完整路径）——文件按设计不搬走，所以也不能让它们从界面上消失 |

界面默认深色，状态栏右下角有「主题 深色 / 浅色」开关，点一下即时整窗换色（实测 51ms），
选择记在 `app-settings.json` 里，下次启动照旧。深浅两套调色板都在 `ui.py` 的
`DARK` / `LIGHT`，颜色只在那里出现字面值，其余模块一律引用 token。

## 目录布局与下载存放

只有**配置和缓存元数据**在 C 盘，**视频文件默认在 exe 同级目录**（可在
「下载与合并」页的「下载位置…」里改到别的磁盘）：

| 位置 | 内容 |
| --- | --- |
| `<保存位置>\下载\<剧名>\` | 解密后的可播放分集、合并成品（用户唯一需要关心的目录） |
| `<exe同级>\.cache\downloads\<jobId>\` | core 下载的**加密** `media.mp4`，用于断点续传和合并 |
| `%LOCALAPPDATA%\ZhenguoJian\` | 登录态、配置、`app-settings.json`（保存位置）、`download-location.json` 重定向指针 |
| `%LOCALAPPDATA%\ZhenguoJian\logs\` | 核心日志与播放器日志（`mpv.log`；播放失败时先看这里） |
| `%LOCALAPPDATA%\ZhenguoJian\covers-v1\` | 海报原图缓存（红果给的多是 HEIC，少数 JPEG），按内容哈希命名 |
| `%LOCALAPPDATA%\ZhenguoJian	humbs\` | HEIC 经 ffmpeg 转出的**小 JPEG**（缩到 320 宽，单张约 40KB；总量超 300MB 自动淘汰旧的），界面直接显示它 |

保存位置默认是 exe 所在目录，所以默认布局仍是 `<exe同级>\下载\`。换位置只
影响**以后**下载/合并的落盘：已经下好的文件不会被搬动（库里已有的播放记录
照旧可用，索引会原样带到新位置，不会在后台重新解密一遍），内部加密缓存也
始终留在 exe 同级目录。

启动时程序会写一份 `download-location.json` 把 core 的下载根指向
`.cache\downloads`，因此 C 盘不会堆积视频。加密原件**不删除**——core 每次都会
校验本地文件存在，删掉会让任务变成「本地文件缺失，请重新下载」。

分集文件按 `剧名 第NNN集.mp4` 命名（集号补零到 3 位，总集数过千时补 4 位，
所以字典序就是集数序）；接口给的章节标题只有比集号多出内容时才拼在后面，
例如 `第005集 大结局`、`第1000集（终）`——纯粹重复集号的标题不会再抄一遍。
删除下载任务时对应索引（`episodes.json`）会同步清理。

环境变量 `ZHENGUO_DATA` 可改写配置根目录，`ZHENGUO_MPV` 可指定外部 mpv。

## 取流路径（2026-10）

播放接口只认**已注册设备**：核心先走 `device_register` 提交 openudid/udid 等设备指纹，
拿到 `device_id` / `install_id` 并持久化复用；未注册设备请求播放接口只会得到
HTTP 200 + 空 body。之后所有 App 请求都带完整签名头（X-Gorgon / X-Argus / X-Ladon 等），
按以下顺序取流：

1. `POST /novel/player/multi_video_model/v1/`（详情页场景，不带 `dr_scene`）
2. 同一个直取接口换新注册设备重试（空包时）
3. 同一个直取接口把 `device_level` 从 3 提到 4（编码不兼容时）
4. 旧直取 `POST /novel/player/video_model/v1/`
5. 网页 cookie 播放页
6. 公开 360p 端点

`preload` 场景（`multi_video_model/preload/v1`）从 2026-10-29 起对同样的请求体稳定回
200 空包，已不再使用；参考客户端也只用详情页场景。前几步能拿到 360p–1080p 全档位和
CENC 密钥（`spade_a`），单集解析约 0.2–0.6 秒。

> 参数要和参考客户端逐字一致：query 里只有设备字段加 `_rticket`，**不能带 `ts`**。
> 多一个 `ts=<秒>` 时目录/详情照常返回，但取流接口会稳定回 200 + 空 body，下载于是
> 掉到网页 360P 兜底，而且每次空包都要重试，表现就是「又慢又只有 360P」。
> `TestSignHongguoRequestKeepsReferenceQuery` 会盯住这一点。

除了参数，另有两处必须和参考客户端对齐，否则取流会间歇性空包（表现为播放/切集很慢、
偶尔 360P）：

1. **TLS 指纹**：App 接口（`api5-normal-sinfonline*.fqnovel.com`）走
   `bogdanfinn/tls-client` 的 Chrome 指纹；用 Go 默认 `net/http` 指纹时同样的
   URL/body/签名只有约 1/7 成功率，每次失败还要重试 5 秒。
2. **签名头数量**：播放类请求只带 `X-Gorgon / X-Khronos / X-Ladon / X-Argus` 四个；
   多带 `X-Helios / X-Medusa` 会触发风控空包（实测同一设备同一集 1/3 → 去掉后 3/3）。
   详情/目录接口仍带六头。

`TestSignHongguoRequestKeepsSixHeadersForDetail` 与
`TestSignHongguoRequestKeepsReferenceQuery` 一起守住这两条（取流四头、详情六头）。

下载队列还会把同一部剧排队中的分集按接口上限（15 集/次）批量预取片源并缓存，
下载任务直接命中缓存，不再逐集请求取流接口——实测 20 集队列全部 1080P，2 次批量
请求 0.8 秒拿完。同一部剧只要 App 接口成功拿到过一次片源，个别集被风控瞬拒时
不会再把网页 360P 兜底当成成功，而是自动排队重试（45/90/180 秒）。

## 下载后自动解密

core 下载完成的是 **CENC 加密态** `media.mp4`，直接播放会卡死。下载任务
进入 `completed` 后，`library.EpisodePublisher` 立刻在后台执行：

1. `ffmpeg -decryption_key <key> -i media.mp4 -c copy -movflags +faststart` 解密
2. `ffprobe` 校验确实有视频轨（确认已解密）
3. 落盘到 `下载\<剧名>\<剧名> 第NNN集.mp4` 并写入 `episodes.json`

播放、合并都优先使用这个已解密文件，所以点开就能播。解密失败不会丢数据：
加密原件原样保留，状态栏给出原因。

## 合并是怎么做的

源文件是 **CENC 加密态**，直接 ffmpeg 拼接会得到码流断裂的废片，所以
`media.MergeTask` 的流程是：

1. 校验分集连续性（缺集直接拒绝）
2. `ffmpeg -decryption_key` 逐集解密，用 core 返回的 `decryptionKey`
3. `ffprobe` 采集签名；签名不一致或编码不支持时统一转码
4. concat 拼接
5. `-xerror -err_detect explode` 完整解码校验 + 时长校验（容差 0.2%，封顶 30 秒）。
   校验上限按片长放宽（`max(2 小时, 片长/6 + 30 分钟)`），并用「连续 10 分钟没有
   解码进展」判定卡死；几百集的长剧可在合并按钮旁取消勾选「完整解码校验」，
   仍会校验时长、编码和流参数。校验失败或超时**不会删除成品**，会存成
   `…（未完整校验）.mkv` 留在「下载/合并/」里。
6. 输出 `全NNN-MMM集.mkv`，清理中间文件

## 弹幕

在线播放页控制条上的「弹幕」按钮（快捷键 `D`）开关弹幕，选择记在 `app-settings.json`。

- 数据来自核心的 `danmaku` 动作：先 `resolve` 拿播放会话，再按 30 秒窗口取；
  每窗上限 90 条（接口限制，和官方 App 一致）。
- 按播放位置懒加载：取当前窗口 + 预取下一窗；拖进度条跳到没取过的区间会即时补。
  取到的窗口合并后重建字幕，用 mpv 的 `sub-reload` 增量刷新，不用反复挂轨。
- 渲染是把弹幕写成 ASS（`%TEMP%\zhenguojian-danmaku\<剧集>.ass`）挂成字幕轨：
  滚动用 `\move`，白字黑边，字号按画面短边自动定，竖屏 1080×1920 也不变形。
- 透明度：控制条「透明 NN%」点开是个竖向滑条，往上更实、往下更透（20%–100%），
  改完立即重建字幕并 `sub-reload`，选择记在 `app-settings.json`。透明度写在
  ASS 样式的主色/描边/阴影 alpha 上，不影响滚动动画。
- 平台对个别设备会抽样返回（一窗只回十几条）；同一窗口最多重试两次，仍被抽样
  就按实际条数显示。颜色和顶部/底部弹幕接口里有，但核心目前没解析，第一版只做
  白色滚动。
- **下载弹幕（可选）**：「下载与合并」页勾选「下载时保存弹幕」后，每集解密完成
  会在成品旁写同名 `.ass` 和 `.danmaku.json`；本地播放自动挂载，默认关闭。全量
  抓取走核心的 `danmakuAll`，会按 cursor 里的 30 秒窗口直方图跳过空窗，不再由
  Python 每窗固定等 3 秒。

## 从源码重新构建

### 一键打包（推荐）

双击本目录的 `一键打包.bat`（等价于 `powershell -ExecutionPolicy Bypass -File build\build-win.ps1`）。
脚本依次自动完成：关闭占用产物的旧实例（selftest/旧版程序残留会锁住 `dist\runtime`）→ 探测本地代理
（默认 `http://127.0.0.1:17890`，不通自动直连）→ 准备 `.venv-build` 构建依赖（requirements 钉版在
新 Python 上装不上时自动退兼容最新版）→ `build.py`（vendor 过期出现 `undefined: core.XXX` 时自动
`go mod vendor` 同步后重试）→ `--selftest` 全链路自检并清掉测试落盘 → `package.py` 出 `真果鉴.zip`。

参数：`-SkipSelfTest`（接口异常仍想先出包）、`-SkipZip`、`-MpvPath <mpv.exe>`、`-Proxy <url>`、
`-FreshDeps`（重建 venv）。selftest 结果以本轮新写的 `dist\selftest-report.json` 为准，未通过则
不生成 zip。

> **这份一键脚本不在版本库里**：`git` 只跟踪 `build\build.py` 与 `build\package.py`，
> `build-win.ps1` 没有入库，而多机同步用的 Syncthing 忽略规则里带 `**/build`
> （`zhenguojian\build\` 整目录都不传），所以 clone 或换机后这两样都会缺。
> 缺了会有两种表现：`一键打包.bat` 直接报 `MISSING build-win.ps1`；`git status`
> 把 `build\*.py` 显示成「已删除」。补的办法二选一：从主开发机手动拷
> `build\build-win.ps1` 过来，或者跳过一键、直接按下面「手动步骤」走 / 用 CI 产物。

### 手动步骤

```
python build\build.py
```

依次：编译 Go sidecar → 归位 mpv/ffmpeg → PyInstaller onefile。
Go 依赖走 `goproxy.cn`；离线时若 `runtime\sidecar.exe` 已存在则沿用旧件。

出成品包（`dist\真果鉴.exe` + `runtime\` + README + 空的 `下载\`、`.cache\downloads\`
打成一个 `真果鉴.zip`，约 153 MB）：

```
python build\package.py
```

改完代码后建议跑一遍成品自检再发包：

```
dist\真果鉴.exe --selftest
```

开发态运行（不走打包）：

```
python app\run.py
```

## 代码结构

```
sidecar/main.go             常驻 stdio JSON-lines 服务，6 槽并发，id 回显
app/run.py                  入口
app/zhenguojian/
  core_client.py            核心客户端，id 匹配所有 API
  player.py                 MpvSession（管道 IPC）+ PlayerPane
  media.py                  probe / MergeTask（解密→统一→拼接→校验）
  downloads.py              下载队列面板（完成后触发自动解密）
  library.py                 EpisodePublisher：解密 + 按剧分目录入库
  decrypt.py                 ffmpeg -decryption_key 解密与校验
  danmaku.py                 弹幕抓取窗口 + ASS 字幕生成（mpv 渲染，不用 Qt 覆盖层）
  widgets.py                CoverLoader(HEIC) / CoverGrid / EpisodeList
  tasks.py                  Worker / TaskRunner / _Relay（回调回 GUI 线程）
  main.py                   主窗口 5 页签
  tools.py                  资源定位（含程序图标路径）
  app.ico                   程序图标：窗口 / 任务栏 / exe 内嵌
  selftest.py               --selftest 全链路自检
build/build.py              打包脚本
```

## 依赖说明

- Python 3.9 + PyQt5 + pywin32（命名管道）
- Go 1.24（sidecar）
- mpv / ffmpeg 静态二进制
