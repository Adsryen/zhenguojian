# v1 ↔ v2 右键菜单对账（清单级对账第五面，也是最后一面）

v1 侧全文只有一处自定义右键菜单：`widgets.py:705-721`（详情页简介控件）
```python
copy = menu.addAction("复制");              copy.setEnabled(hasSelection())
copy_all = menu.addAction("复制全部简介")
select_all = menu.addAction("全选")
```
其余控件走 Qt 默认菜单（`QLineEdit` 默认给 撤销/剪切/复制/粘贴/删除/全选）。
v1 只有这一处 `def contextMenuEvent`（grep 全仓确认）。

v2 侧 `services/contextMenu.ts` 是全局一处挂载，按 target 分四类：

| target | v1 | v2（本轮后） |
|---|---|---|
| 输入框（可编辑、非只读） | Qt 默认：撤销/剪切/复制/粘贴/删除/全选 | 剪切 /（有选区时）**复制** / 粘贴 / 全选；密码框不给粘贴 |
| 页面有选区 | 复制 / 全选 | 复制 / 全选 |
| 简介块（`data-ctx-copy-all="summary"`） | 复制(禁用若无选区) / **复制全部简介** / 全选 | 复制(有选区才给) / **复制全部简介** / 全选 —— 本轮补 |
| 纯媒体且无选区 | Qt 默认（图片菜单） | **不弹**（空菜单不显示，任务书约定） |

## 两处刻意不同，都不是遗漏

1. **v1「复制」在无选区时是禁用行，v2 直接不给这一行。**
   菜单里一行点不动的东西只会让人以为程序坏了；v2 的判据是"能做的事才出现"。
   `contextmenu_verify` 场景C 的断言把这点钉住（`"复制" not in labels`）。
2. **v1 输入框有「撤销」（Qt 自带），v2 不补。**
   `document.execCommand('undo')` 打在 Vue 受控输入上**不会同步 v-model**：
   界面上的字回来了，`input` 事件没发，模型里还是旧值——
   这是"看着能用其实把界面和数据劈开"，比缺这一项更糟。
   要补正确做法是自己维护撤销栈或改走原生菜单，属于单独一件事，不夹带在对账里。

## 复制全部简介的实现要点

- `copyAllText()` 取块内文本时**剔除 `[data-ctx-strip]`**（折叠态那个「展开」label 是控件，不该进剪贴板）。
- 折叠只是 CSS：DOM 里始终是整段文本，所以复制到的是全文，与 v1 `toPlainText()` 一致。
- `COPY_ALL_KINDS` 是显式白名单（现在只有 `summary`）。**不做 `t('ctx.what.' + kind)` 拼接**：
  拼出来的键名静态门禁查不到，写错了也不报错——这类"看起来灵活其实失去校验"的写法
  本任务已经犯过两次（`${action}失败：${m}` 式拼接文案、以及过滤器名单）。

## 顺带：我给 `run_all` 加过一条"对账"，量出来发现它太吵，于是降级

看到"声明的 `check()` 数"与"实际打印的 PASS/FAIL 行数"对不上（6 个脚本），
我以为抓了一批静默漏测。逐个判读后：**只有 1 个是真被条件跳过**
（`contextmenu_verify` 里包在 `if img.count() > 0:` 的那条——已改成硬判：
找不到可命中的 img 就 FAIL 并说明原因，不再静默通过）。
其余 5 个是**口径差**：循环里的 `check()` 会打印多次、失败分支里的 `check()` 平时不打印。

结论：这条启发式**不能当门禁**，只配当人工判读的线索，所以改成
`run_all.py --audit-checks` 显式开启、默认关掉；输出措辞也从"静默跳过"改成"候选"。
（"狼来了"的门禁比没有门禁更糟——这条和第二轮以来我一直守的规矩同源。）
